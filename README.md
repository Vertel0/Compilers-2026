# 🚀 Инструкция по развертыванию рабочего окружения

Для выполнения практической работы вам необходимо собрать зависимость QBE, настроить проект через CMake Presets и запустить автоматические тесты.

# 0. Подготовка рабочей директории
Для выполнения практических работ и запуска тестов необходимо подготовить изолированное окружение.

### Создание рабочей директории
Рекомендуется создать отдельную директорию `workdir`, в которой будет вестись вся разработка:
```bash
mkdir workdir
cd workdir
```

### Настройка виртуального окружения Python
Для запуска тестов требуется интерпретатор Python и несколько вспомогательных пакетов. Чтобы не засорять системное окружение, создайте виртуальное окружение:
```bash
# Создание виртуального окружения
python -m venv qbe-venv

# Активация окружения
source qbe-venv/bin/activate
```
После активации приглашение терминала изменится — появится префикс `(qbe-venv)`.

### Установка зависимостей
Установите необходимые Python-пакеты:
```bash
pip install lark
```
`lark` используется для парсинга и тестирования промежуточного представления QBE.

Альтернативный способ -- установить зависимости, которые написаны в файле [requirements.txt](./requirements.txt):
```bash
pip install -r requirements.txt
```

Теперь можно приступить к сборке самого компилятора QBE и рабочего эскиза решения. Детальные инструкции по сборке написаны в следующем разделе.

# 1. Сборка и локальная установка QBE
Поскольку QBE является внешней зависимостью, мы соберем его из исходников и установим в изолированную директорию (локально для вашего пользователя), чтобы не засорять системные папки.

## 1.1 Сборка QBE
```bash
git clone https://compilers.ispras.ru/git/qbe.git
cd qbe
make
```

# 1.2 Установка QBE
Установка выполняется в локальную папку (замените /path/to/qbe на ваш путь)

Например: `DESTDIR=$HOME/qbe_local`
```bash
make DESTDIR=/path/to/qbe install
```

После выполнения команды исполняемый файл будет доступен по пути `/path/to/qbe/bin/qbe`.

Следующим шагом необходимо вернуться в корень настоящего проекта:
```bash
cd ..
```

# 2. Создание пользовательского пресета

Чтобы переопределить путь к QBE, не меняя основной конфиг проекта, создайте файл `CMakeUserPresets.json` в корне репозитория. Он автоматически наследует настройки от серверного пресета `ci-server`.

Создайте файл `CMakeUserPresets.json` со следующим содержимым:
```json
{
  "version": 3,
  "configurePresets": [
    {
      "name": "local-dev",
      "inherits": "ci-server",
      "displayName": "Local Development Preset",
      "cacheVariables": {
        "QBE_ROOT_DIR": "/path/to/qbe"
      }
    }
  ],
  "buildPresets": [
    {
      "name": "local-dev",
      "configurePreset": "local-dev"
    }
  ]
}
```
**Важно**: В переменной `QBE_ROOT_DIR` указывайте тот же путь, который вы использовали в параметре `DESTDIR`.

# 3. Сборка проекта и запуск тестов

Используйте стандартные команды CMake для подготовки бинарных файлов и запуска автоматической проверки.

### Шаг 1: Конфигурация
```bash
cmake --preset local-dev
```

### Шаг 2: Компиляция
```bash
cmake --build --preset local-dev
```

### Шаг 3: Тестирование (CTest)

Запустите проверку вашего компилятора на наборе тестов `*.ssa`. В случае несовпадения с эталоном (`.ans`), подробная информация об ошибке будет выведена в консоль. Для запуска тестов рекомендуется использовать подготовленные `CMake Preset`:
```bash
ctest --preset public-suite
```

# 💡 Полезные команды
`python utils/tester.py -c dce -b build/dce -t test/dce` - ручной запуск тестов для `DCE` \
(вместо `dce` необходимо указать выполняемое в данный момент задание).

`ctest --test-dir build -N` -- вывести список тестов.

`ctest --test-dir build -R test_name` — запустить только один конкретный тест.

`ctest --test-dir build -j4` — запустить тесты параллельно (ускоряет проверку).

`ctest --test-dir build --verbose` — показать полный лог выполнения каждой команды.
